## M1 — rng stream plumbing (structural, hash-neutral)

### Changes
- `src/hotwell/rng.py` (new): `STREAM_IDS` (a `MappingProxyType` over a literal dict of
  25 entries: `sensor.<instrument>` 1000–1021 in the current `OBSERVATION_SPEC` order,
  `load.vital` 2000, `load.nonvital` 2001, `operator` 3000) and `StreamBank`.
  `stream(name)` lazily builds and caches
  `np.random.default_rng(np.random.SeedSequence([seed, STREAM_IDS[name]]))`.
- `src/hotwell/simulator.py`: `self.streams = StreamBank(seed)`; `self.rng` kept, with a
  comment marking it unused; module docstring updated.
- `tests/test_rng.py` (new, 10 tests).

### Decisions
- **Literal IDs, not derived from `OBSERVATION_SPEC` order.** Derivation would renumber
  every stream if the instrument list were reordered or extended in the middle.
  Rejected for that reason. A coverage test supplies the "derived" guarantee: every
  instrument must have a stream.
- **Entropy `[seed, id]` with each id < 2^32.** NumPy encodes each int as minimal
  little-endian uint32 words, so with a single-word id as the last word, (seed, id) →
  entropy is injective. A test asserts ids < 2^32.
- **Spaced series (1000/2000/3000)** leave room to append within each family. Purely
  cosmetic, since IDs only have to be unique.
- **Numpy version joins the determinism scope.** NumPy guarantees the bit-generator
  streams but not `Generator` distribution algorithms. A pinned-draw test makes an
  upgrade fail loudly instead of breaking hashes silently.
