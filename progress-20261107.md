## M1 — rng stream plumbing (structural, hash-neutral)

### Changes
- `src/hotwell/rng.py` (new): `STREAM_IDS` (a `MappingProxyType` over a literal dict of
  25 entries: `sensor.<instrument>` 1000–1021 in the current `OBSERVATION_SPEC` order,
  `load.vital` 2000, `load.nonvital` 2001, `operator` 3000) and `StreamBank`.
  `stream(name)` lazily builds and caches
  `np.random.default_rng(np.random.SeedSequence([seed, STREAM_IDS[name]]))`.
- `src/hotwell/simulator.py`: `self.streams = StreamBank(seed)`; `self.rng` kept, with a
  comment marking it unused; module docstring updated.
- `tests/test_rng.py` (new, 10 tests).

### Decisions
- **Literal IDs, not derived from `OBSERVATION_SPEC` order.** Derivation would renumber
  every stream if the instrument list were reordered or extended in the middle.
  Rejected for that reason. A coverage test supplies the "derived" guarantee: every
  instrument must have a stream.
- **Entropy `[seed, id]` with each id < 2^32.** NumPy encodes each int as minimal
  little-endian uint32 words, so with a single-word id as the last word, (seed, id) →
  entropy is injective. A test asserts ids < 2^32.
- **Spaced series (1000/2000/3000)** leave room to append within each family. Purely
  cosmetic, since IDs only have to be unique.
- **Numpy version joins the determinism scope.** NumPy guarantees the bit-generator
  streams but not `Generator` distribution algorithms. A pinned-draw test makes an
  upgrade fail loudly instead of breaking hashes silently.

## M3 — sensor noise, new sensor fault kinds, I5 TRUTH_SIGNALS (hash-neutral)

### Changes
- `sensors.py`: pipeline `truth → lag → bias/drift → noise → stuck → clamp → quantize`;
  `SENSOR_FAULT_KINDS` (stuck, bias, drift, lag, noise_increase); `SensorFault` gains
  `rate`, `max_bias`, `tau_s`, `factor` (defaults keep the old constructor calls
  working) and validates itself; `NoiseSpec`; `SensorBank(noise, streams, dt)` with
  block-buffered draws (4096 per stream refill), a unit AR(1) state, and `last_draws`.
- `simulator.py`: builds the bank from `cfg["sensors"]["noise"]` and `self.streams`; the
  init sample is `noisy=False`; the `sensor_fault` event passes all fault params.
- `scenario.py`: `_check_sensor_fault` (target, kind, required params, ranges) at load.
- `historian.py`: `TRUTH_SIGNALS`, `INDICATION_SIGNALS`.
- `baseline.yaml`: documented empty `sensors: noise: {}`.
- `tests/test_m3_sensors.py` (new, 19 cases).

### Decisions
- **Draw always, even with sigma = 0 everywhere.** This is the simplest rule that
  satisfies I2 with no special cases. It costs +2 % on T11, measured. Rejected: drawing
  only when noise is configured. That would also satisfy I2 (both twins share config),
  but it adds a branch someone could later "optimize" into per-instrument skipping, which
  breaks I2. The mutation check shows the twin test catches that.
- **Unit AR(1) state, scaled by sigma·factor at output.** `noise_increase` then rescales
  amplitude without touching the underlying sequence, and white noise is the a = 0 case
  of the same code (u = z exactly).
- **Init sample is noise-free and draw-free.** Controllers are initialised bumpless at
  those values, and the draw count is defined per `step()`.
- **One fault per instrument** (the existing dict semantics). The benchmark injects one
  fault per item; combined faults can come later if needed.
- **Lag initialises at the current truth** when the fault starts, so onset makes no
  jump. A jump would give the fault away.
- **Noise lives in the plant config, not the scenario.** It is a property of the
  instruments. The bench generator passes a config dict.
