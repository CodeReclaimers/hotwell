# Progress — 2026-08-29 (hotwell core)

## Session: 0.3.0 — station-service pump motor loads

### Context

During panel play Alan observed that starting condensate/feed pumps does not
change generator load. Diagnosis: `Loads.p_elec` summed only the two abstract
blocks; pump motors existed electrically only as the ammeter display proxy
(`Plant._pump_current`) — the D10 abstraction. Alan chose (from three options:
core task now / HANDOFF proposal / config-gated default-off) to **execute as
hotwell 0.3.0, default ON, re-measure the tables, panel re-pins after**.

### Summary of changes

- `components/pumps.py`: `PumpParams.p_motor_rated` [W] (default 0 = feature
  off, pre-0.3 behavior for custom configs).
- `components/loads.py`: `p_elec(..., station_service=0.0)`; docstring notes
  frequency-independence (consistent with the pump model, whose shaft speed
  does not track bus frequency).
- `plant.py`: `_pump_motor_power` — same 25 % no-load floor +
  hydraulic-power-proportional shape as the ammeter proxy, so wattage and
  current agree by construction; a stopped or **tripped** pump draws nothing
  even while coasting (contactor open; inrush not modeled). Summed per
  evaluation in `deriv` from the solved path flows; `Aux.p_station_service`.
- `simulator.py` `initialize_steady_state`: **`load_mw` = commanded GROSS
  output.** Blocks absorb `load_mw − p_ss` via fixed-point iteration around
  the root solve (contracts ~1/80 per pass, 1 kW tolerance, break before
  re-anchoring so the returned state is an exact equilibrium). New
  authoritative equilibrium gate: scaled |ydot|max < 1e-7 raises — replacing
  reliance on hybr's progress flag.
- `baseline.yaml`: `p_motor_rated` 40 kW (condensate; 30.3 kW hyd, η≈0.76)
  and 1.0 MW (feed; 821 kW hyd, η≈0.82).
- `scripts/run_scenario.py --events`: prints alarm transitions so the HANDOFF
  cascade tables regenerate from committed code.
- `tests/test_station_service.py`: 6 tests (anchors preserved, FP-2 visible
  on the meter, CP-2 small-but-real, tripped-coasting draws nothing, dead bus
  zero, p_motor_rated=0 restores 0.2.0 behavior).
- Version 0.3.0, CHANGELOG, HANDOFF section + re-measured tables.

### Key decisions (alternatives rejected)

- **Gross-output semantics (Option B).** Alternative A — blocks at full
  `load_mw`, gross ≈ 61 MW — was rejected because it invalidates the
  plan-locked §5.1 anchors (steam 76.9/feed 87.1 kg/s, 60.0 MW @ 60 Hz) and
  exceeds what Alan approved (timing re-pins only). Under B the anchors are
  preserved to the displayed digit.
- **Draw shape mirrors the ammeter proxy** rather than a separate motor
  model: one source of truth for "how loaded is this pump", consistency by
  construction. Deliberate inconsistency left in place: the ammeter (s-gated)
  still reads ~25 % during a trip coast-down while the draw is zero
  (mode-gated); changing the sensor would perturb observed values for a
  display-only refinement — flagged, not fixed.
- **Frequency-independent draw**: the hydraulic model ignores bus frequency,
  so a frequency-dependent electrical draw would let power and hydraulics
  disagree.

### Bugs found and fixed along the way

1. **hybr "not making good progress" on warm-started re-solves.** The
   fixed-point's later passes start nearly converged; hybr's trust region
   stalls, and whether it stalls depends on the path-solve warm-start caches
   (`_qw_cond/_qw_feed`) — the residual function is stateful, so the failure
   was call-history-dependent (T9's two_state case failed only after the
   astrom_bell test ran first in the same process). Fix: judge each solve by
   its final residual (≤ 1e-6 scaled) and gate the returned state on the
   T2-grade measure directly (scaled |ydot|max < 1e-7).
2. **Final `set_blocks` after the accepted solve perturbed the state**
   (residual norm 1.2e-6 > T2's 1e-7). Fix: break before re-anchoring; the
   state returned is an exact equilibrium of the blocks as set (residual
   2.9e-16 measured).
3. Scratch-script false alarm (not a model bug): `Simulator.run(t)` takes an
   ABSOLUTE time, not a duration — an early probe "showed" CP-2 never
   spinning up because `run(30)` from t=35 does nothing.
